# 非规范 Markdown 的降级入库

2026-11-11，任务分支 `feature/unstructured-markdown-ingest`。

## 导入入口与边界

默认 `ingest` 继续执行严格 front-matter 校验。仅显式传入 `-allow-unstructured` 时，缺失 front-matter 或必需字段、但有正文的 Markdown 才进入待审核通道。无正文、front-matter 未闭合或明确写出但无效的日期仍报错。目录说明 `README.md` 仍跳过。

待审核文档的 ID 为 `synthetic_` 加原始文件 SHA-256 前 12 位，另保存完整 SHA-256 供碰撞检查；版本固定为 `unversioned`，状态为 `needs_review`，业务生效日为空。导入时间只作审计，不作为业务日期。显示标题取已声明的标题，否则取文件名；正文前几行的版本字样仅存为 `version_hint`，不当作正式版本。

## 重复与审核

相同原始内容再次导入是幂等操作；异名同内容复用已有索引并记录文件名别名。同名异内容独立入库，新增 `possible_duplicate_name` 审核提示，不生成 `Replaces`。合成 ID 前缀碰撞但完整 SHA-256 不同则报错，不能误判为副本。需要人工判断同名冲突是否是真正的版本升级，确认后再以正式元数据重新入库。

待审核文档可被 CLI 和 HTTP 搜索，搜索结果标记未认证来源。正式问答与评测使用独立的已认证索引，待审核资料不会改变 BM25 词频统计或正式结果的排序；它也不参与时间、替代或指针关系裁决。只命中待审核资料时返回 `insufficient_evidence` 且零引用。这样避免把 `unversioned` 或空业务日期伪装成现行规范。

## 保留限制

SHA-256 按原始字节计算，换行或文件编码变化会产生新身份；这类疑似副本交人工处理。当前没有管理 UI、自动审核或自动版本合并，也不依据文件名和正文提示建立关系。
