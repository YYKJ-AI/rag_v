# 跨版本指针关系：V1 最小闭包

## 设计选择

关系是可审计的事实，不是文本替换。`v2` 的“沿用”句和 `v1` 的具体条款分别保留在原文 Section 中；回答必须同时显示两处来源，不得将 `v1` 条款表述为 `v2` 原文。当前只实现 `references` 和 `inherits` 两种关系类型。`references` 说明指向何处，不自动继承目标事实；`inherits` 在严格校验后允许把目标条款作为当前回答的第二证据。

采用最小必要闭包：不建完整知识图谱、任意节点体系、通用遍历器、多跳关系或 `contradicts` 自动处理。文档级 `Document.Replaces` 保留原代码路径，继续负责当前和历史版本裁决，不强迫关系表接管。这避免过早抽象掩盖版本裁决的业务差异。

## 数据与输入约定

导入时在 `Chunk` 上保存 `Kind=pointer` 与 `Relation`：源 Chunk ID、目标文档 ID、目标版本、目标 Section ID、关系类型、解析状态和原始指针句。保存的关系随 JSON store 持久化；目标文本不复制进源块。

V1 的可解析目标必须在指针句里明确写出 `document_id@version#section-id`，例如：

```text
申请人条件沿用 guide@v1#sec-1，不作调整。
申请人条件参照 guide@v1#sec-1。
```

其中 `sec-1` 指向导入后的 Section ID；它属于该版本的定位符。一个句子有零个或多个显式目标时，关系保留为 `unresolved`。`parsed` 仅表示目标 ID 的语法可解析，不表示目标文档已导入或关系已成立；实际目标在查询时查验。V1 不从“原规定”“条件不变”等含糊表述猜文档或 Section，也不把自动发现当作已核验的关系。已有同版本正文不可静默改写，修订应升版本。

## 查询与回答

查询先按原有 `effective_date`、`valid_until`、`scope_keys` 和 `Replaces` 过滤当前候选。命中当前指针句后，只做一次目标 Section 查找；校验目标存在、版本明确、在源版本生效时已生效、源与目标的机器范围键有交集（或一方为 `*`），且继承目标不是另一个需要跟随的指针。缺失机器范围键时 V1 不猜测兼容性。旧版本只作为“被引用条款”进入结果，不作为当前独立版本混入普通候选。

`inherits` 的回答结构为：现行来源 `v2` 的沿用声明；被引用来源 `v1` 的具体条款；明确说明具体原文来自 `v1`。两条 Citation 分别标记 `current_pointer` 和 `inherited_clause`，摘录都必须能在各自 Section 原文中定位。`references` 仅能回答“引用/参照了哪个条款”这类来源问题，只标记源声明为 `current_pointer`；问目标条款具体条件时不能据此推出继承，返回 `insufficient_evidence`。

目标缺失、多个目标、同节循环、第二跳、范围不符或未来目标均拒答。多子问题不进行指针跟随，维持保守拒答。普通证据模板不能把指针句当作具体条件。

## 能力边界与演进

关系处理不解决“最低年龄”与“年满十二周岁”的语义等价，也不解决无关引用的精排问题。离线模式只能跟随明确可核验的关系；未来 P2 模型可以发现候选关系和重排候选，但不能裁决关系真相。候选关系必须经过规则校验或人工确认后才能入库，模型也不能自行确立版本有效性或伪造引用。待真实语料需要新关系时，再增加具体业务逻辑；不预先编写通用图遍历框架。

当前检索与证据抽取仍有词项和阈值上限，相关缺陷见 `bug.md`。本功能的验收采用虚构 v1/v2 正反例和原有演示回归，不能把 21 条演示评测通过解释成语义充分性得到证明。
