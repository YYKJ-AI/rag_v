## 既有缺陷（非本次任务引入）

### BUG-1：评测汇总计数与逐条结果不一致 — 已解决

- **复现：**在演示资料上运行 `ragbot evaluate`；拒答案例 Q12 的逐条 `pass` 为 true，但汇总仍显示 13/14。
- **影响：**交付报告的通过数及失败案例说明不可靠。
- **定位：**`internal/evaluate/evaluate.go` 修改 `rec.Pass` 后，汇总仍使用修改前的 `pass` 变量。
- **修复与复测：**`fix/evaluation-metrics` 改为从逐条 `Pass` 汇总；隔离复跑 14 条查询，汇总 14/14 与逐条一致，拒答 Q12 计入通过。

### BUG-4：多来源检索与有出处指标口径过宽 — 已解决

- **复现：**旧代码的 `expect_docs` 有任意一份进入前五便将 Hit@5 置为 true；有出处率以全部 14 条为分母，包含正确拒答。
- **影响：**跨文档查询可漏检来源却通过，拒答会降低有出处率。
- **修复与复测：**要求全部标注文档命中；只以有答案案例为 Hit@5、有出处与来源核验的分母。聚焦测试覆盖缺少任一来源；演示集复跑为 13/13、13/13、13/13，拒答另计 1/1。

### BUG-5：整数毫秒记录丢失快速查询耗时 — 已解决

- **复现：**单次 `time.Since(...).Milliseconds()` 将多数查询截断为 0ms。
- **影响：**逐条与平均耗时不便比较。
- **修复与复测：**每题连续运行 64 次回答并记录单次平均的小数毫秒；隔离复跑的 14 条耗时均大于 0，平均约 0.224ms。耗时随环境变化。

### BUG-2：未来生效版本可进入“现在”的回答 — 已解决（问答路径）

- **复现：**导入 `effective_date` 为 2030-01-01、`replaces: art-guide@v2` 的新版本；在 2026-11-11 提问当前申请时限，可引用未来版本。
- **影响：**现行答案可能引用尚未生效的规定；显式历史查询也可能把当时有效的版本标成已废止。
- **定位：**替代状态在导入时无条件改变；未指定 `as_of` 时未按业务日期过滤。
- **修复与复测：**`fix/version-scope` 在回答前按本地业务日期或显式历史日期筛选，按有效日、终止日、显式替代及范围裁决，历史版不再按导入状态误标“已废止”。聚焦测试验证未来版在生效前不引用、生效后才切换、历史时点引用 v1，跨 ID 替代也有效。导入时的 `Status` 仅保留关系记录，不作为问答有效性依据。

### BUG-6：文档级替代与部分修订资料不匹配 — 已解决（演示语料）

- **复现：**原演示 v2 仅列出变更条款，却声明完整替代 v1；按文档级替代严格过滤后，当前申请资格缺少完整原文。
- **影响：**只引用 v2 的“申请人条件不变”不足以直接回答具体条件。
- **修复与复测：**演示 v2 整理为包含全部现行条款的完整整合版，保留四项材料、七日初审等修订口径。隔离重建与 14 条评测通过；Q01 当前引用 v2 完整资格句。真正的部分修订应另建适用范围明确的补充资料，不可冒用完整替代关系。

### BUG-7：无效日历日期被当作有效查询日 — 已解决

- **复现：**旧 `parseYMD` 把 2025-02-29 和 2025-02-30 自动归一化到三月。
- **影响：**历史查询可能落入错误版本窗口。
- **修复与复测：**校验日期构造前后年月日一致；聚焦测试验证两个无效日期被拒绝，2024-02-29 保持有效。导入的 `valid_until` 也检查日期和先后顺序。

### BUG-8：检索忽略真实子块 — 已解决

- **复现：**旧索引忽略导入生成的 `Chunk`，用整节伪子块评分；`Hit.Chunk` 为空，父块中没有被导入子块覆盖的词仍可虚假命中。
- **影响：**长文局部召回、命中解释和子块去重均失去真实依据。
- **修复与复测：**索引真实子块正文，父块聚合保留最高分子块并返回 ID；聚焦测试覆盖长文、流程、表格、父块独有词不命中、重复建索引和稳定同分排序。全量 Go 测试与 14 条演示评测通过。

### BUG-3：HTTP Engine 共享状态存在并发风险 — 已解决

- **复现条件：**并发调用 `/api/ask`，一个请求推断出时间、另一个未推断时，二者读写同一 `lastInferredTime`。
- **影响：**时间点提示可能串到其他请求；现已添加并发回归测试。
- **定位：**`internal/engine/engine.go` 的可变字段与 `internal/server/server.go` 的后续读取。
- **修复与复测：**`feature/delivery-validation` 移除 `Engine.lastInferredTime`，HTTP 时间提示由当前请求问句的纯函数判断；合并后的 64 个并发 HTTP 请求测试与全量 Go 测试通过。当前环境 `CGO_ENABLED=0`，未运行 `go test -race`；并发行为测试不能代替竞态检测器。

### BUG-9：标题主题剥离误伤通用费用查询 — 已解决

- **发现：**`feature/document-evidence-types` 初版把“申请费用”也从问句删掉，导致原有范围、版本和 HTTP 单测拒答。
- **影响：**旧功能回归，不能验收。
- **修复与复测：**仅在主题片段同时出现在至少三份文档标题时剥离；新增全语料聚焦测试覆盖“艺术节”“星河工作坊”和“申请费用”类查询。全量 Go 测试复测通过，21 条评测通过。

### BUG-10：引用可定位但语义不充分 — 未解决（既有评分边界）

- **复现：**在 12 份资料的参考评测报告中，Q03“盖什么章”同时引用场地报备及补交渠道；Q08“经营性舞台一天多少钱”同时引用场地保证金；Q14“补交方式”同时引用补助申请。Q06 目前只引用报备句，未同时展示紧邻的安全许可句。
- **影响：**`source_coverage` 与 `citations_located` 仍为真，21/21 汇总会掩盖无关或不完整的回答。真实业务使用前必须人工核查。
- **处理：**试过提高词项权重与收紧相对阈值，但使 Q04“现在要交哪些材料”偏向场地通知，已撤回该不稳定调整。保留可定位证据、明确拒答和 README 边界；后续需引入独立的语义相关性标注或更强证据判定，并以保留集验证，不以当前 21/21 作为语义正确性承诺。

## 2026-11-11：跨版本指针任务

### PTR-1：部分修订指针缺少旧版具体证据 — 本任务已解决（明确单跳）

- **复现：**虚构 `guide@v2` 替代 `guide@v1`，新版申请人条件只写“沿用 guide@v1#sec-1”。原问答只筛出当前 v2，无法从被替代版本的指定节获取具体条件及双来源引用。
- **影响：**仅引用“条件沿用”不足以证明年龄和户籍等具体条件；把旧版文本说成新版原文存在审计风险。
- **修复与复测：**保存明确关系并单跳查验旧版指定 Section；回答分别标注 v2 声明与 v1 条款。历史查询仍独立引用当时有效的 v1；缺失、歧义、循环、二跳、未来目标及范围不兼容拒答。聚焦测试和全量 Go 测试通过。

### PTR-2：指针句落入普通事实模板 — 开发中发现并修复

- **复现：**初版在指针校验未处理查询时，普通句子抽取仍可能把“沿用/参照”句当作具体事实输出。
- **影响：**可能在目标未核验时返回貌似有出处的回答。
- **修复与复测：**普通证据集合排除被识别的指针声明；`references` 只回答指向哪里，不能借此继承旧版事实。聚焦测试覆盖参照不继承和隐式指代拒答；全量回归通过。

**仍有边界：**纯词项检索对同义问法的漏召回及 BUG-10 引用语义噪声尚未解决；此任务不调词表或对齐阈值。
