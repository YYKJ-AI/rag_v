## 2026-11-11：修正版本和适用范围

- **分支：**`fix/version-scope`，从 `work/ragbot` 创建；合并目标仅为 `work/ragbot`。
- **原因：**原回答在未指定日期时不做业务日期筛选，未来版可提前成为依据；导入时的 `Status` 会把历史查询中当时有效的版本误标为已废止；文档 `scope` 仅是人读文本，没有可靠的范围键。
- **改动：**回答前按当前本地业务日期、显式日期或问句推断日期过滤所有检索候选，再截取前八；跨文档 ID 的显式替代与有范围约束的替代按有效日裁决。移除检索中依赖导入状态的旧版降权及回答中的过期状态标签。无效日历日期不再被归一化为下一月。
- **改动：**新增可选 `scope_keys`（逗号分隔，`*` 通用）和 `valid_until`；CLI `-scope-key`、HTTP `/api/ask` 的 `scope_key` 传入显式范围。指定范围时未标键文档不作适用猜测。2025 年度历史问答设置有效期；演示 v2 整理为完整整合版，以兑现文档级 `replaces` 的完整替代含义，并为八份演示资料标范围键。
- **影响：**隔离重建后，演示评测仍为 14/14；当前 Q01/Q04/Q05/Q14 不再引用 `art-guide@v1` 或 2025 年度问答，Q09 历史查询仍可引用旧版。`scope=resident` 能引用当前 v2，未知范围拒答。更新了评测参考快照和 README。
- **迁移与限制：**已导入旧版 v2 正文的 `data/store.json` 不会自动覆盖同版本内容，需用新的 `-data` 目录重建演示索引。导入时的 `Status` 是关系记录，不代表任意业务日期的有效状态；实际问答以 `effective_date`、`valid_until`、`replaces` 和请求范围裁决。未指定范围时不推断身份或地区。未解决的句子语义相关性与多类型文档问题留给后续任务。

## 2026-11-11：V1 跨版本指针证据链

- **分支：**`feature/document-pointer-relations`，从非 `main` 的 `work/ragbot` 创建；目标仅为 `work/ragbot`。
- **原因：**真正的部分修订只写“条件沿用旧版”时，现有文档级 `Replaces` 会使旧版退出现行检索；单引用新版本的指针句不足以证明具体条件。补同义词和调对齐阈值不能安全解决版本证据链。
- **讨论结论与改动：**按最小必要闭包增加 `references`、`inherits` 两种关系和 `pointer` 块标记，记录源 Chunk、目标文档/版本/Section、解析状态及原始句；没有写通用图遍历、`contradicts` 自动处理或模型推理。`Document.Replaces` 保留直接版本裁决路径。设计细节见 `pointer-relations.md`。
- **改动：**导入阶段只解析明确的 `doc@version#section`，不猜含糊指代；JSON store 持久化关系。回答阶段最多跟随一次明确 `inherits`，查验目标存在、时间和范围兼容，双来源引用以 `current_pointer` / `inherited_clause` 角色标注并明确说明“具体条款来自 v1”。`references` 只回答指向哪个条款，不借此断言旧条款是现行条件。普通模板排除指针声明。
- **影响：**虚构 v1/v2 的继承查询能同时引用现行声明与旧版具体条款；目标缺失、双目标、循环、二跳、未来目标及范围不合时拒答。旧版不会重新成为当前独立候选。隔离演示 12 份文档导入成功，21/21 开发评测结果未退化。
- **限制：**目标用当前版本内稳定的 Section ID（如 `sec-1`）定位；语法状态 `parsed` 不等于目标已存在。纯词项检索仍可能漏掉改写问法；多子问题中的指针不跟随；BUG-10 的语义引用噪声未解决。独立保留集 H13 失败保存在另一未合并任务分支，本项没有修复或掩盖。
- **合并结果：**聚焦与全量测试通过后，任务分支无冲突合回 `work/ragbot`；`main` 保持不变。

## 2026-11-11：非规范 Markdown 降级入库

- **分支：**`feature/unstructured-markdown-ingest`，从 `work/ragbot` 创建；完成后仅合回 `work/ragbot`。
- **原因：**严格导入要求完整 front-matter；没有 ID、版本或业务日期的资料无法入库，同时不能通过猜测把它们伪装成现行规范。
- **改动：**增加显式 `-allow-unstructured` 通道。按原始文件 SHA-256 生成稳定合成 ID，版本记为 `unversioned`、状态记为 `needs_review`；保留文件名、别名、降级原因和仅作提示的正文版本字样，不伪造业务生效日。精确副本合并别名，同名异内容独立保存并提示审核；带 BOM 的 Markdown 标题正确解析。
- **改动：**搜索保留待审核资料并在 CLI/API 标明未认证；正式问答与评测使用独立的已认证 BM25 索引，待审核资料不进入证据、版本替代或指针跟随，也不影响正式资料的词频统计与排序。更新 README、架构说明和专项设计记录。
- **影响：**默认严格导入维持旧行为；显式降级导入能处理有正文的非规范 Markdown。格式损坏、空正文、明确但无效的日期继续报错。正式问答只命中待审核资料时拒答且零引用。
- **限制：**原始字节编码或换行变化会得到新身份；没有管理 UI、自动审核或自动版本合并。既有 BUG-3、BUG-10 和保留集 H13 仍按原记录开放。
- **合并结果：**最终测试通过后，任务分支无冲突合回原非 `main` 工作分支 `work/ragbot`；`main` 保持不变。
