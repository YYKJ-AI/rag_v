## 2026-11-11：修正版本和适用范围

- **分支：**`fix/version-scope`，从 `work/ragbot` 创建；合并目标仅为 `work/ragbot`。
- **原因：**原回答在未指定日期时不做业务日期筛选，未来版可提前成为依据；导入时的 `Status` 会把历史查询中当时有效的版本误标为已废止；文档 `scope` 仅是人读文本，没有可靠的范围键。
- **改动：**回答前按当前本地业务日期、显式日期或问句推断日期过滤所有检索候选，再截取前八；跨文档 ID 的显式替代与有范围约束的替代按有效日裁决。移除检索中依赖导入状态的旧版降权及回答中的过期状态标签。无效日历日期不再被归一化为下一月。
- **改动：**新增可选 `scope_keys`（逗号分隔，`*` 通用）和 `valid_until`；CLI `-scope-key`、HTTP `/api/ask` 的 `scope_key` 传入显式范围。指定范围时未标键文档不作适用猜测。2025 年度历史问答设置有效期；演示 v2 整理为完整整合版，以兑现文档级 `replaces` 的完整替代含义，并为八份演示资料标范围键。
- **影响：**隔离重建后，演示评测仍为 14/14；当前 Q01/Q04/Q05/Q14 不再引用 `art-guide@v1` 或 2025 年度问答，Q09 历史查询仍可引用旧版。`scope=resident` 能引用当前 v2，未知范围拒答。更新了评测参考快照和 README。
- **迁移与限制：**已导入旧版 v2 正文的 `data/store.json` 不会自动覆盖同版本内容，需用新的 `-data` 目录重建演示索引。导入时的 `Status` 是关系记录，不代表任意业务日期的有效状态；实际问答以 `effective_date`、`valid_until`、`replaces` 和请求范围裁决。未指定范围时不推断身份或地区。未解决的句子语义相关性与多类型文档问题留给后续任务。
- **合并结果：**`fix/version-scope` 在验证通过后无冲突合回 `work/ragbot`；未合入 `main`。
