# ragbot 项目总体架构

> 项目内部文档。最后更新：2026-11-11

## 一句话定位

可溯源知识库问答系统：导入 Markdown 资料 → 检索 → 返回带逐条出处（文档/版本/位置/摘录）的回答，确定性处理版本冲突与证据不足。

## 总体链路

```
┌─────────────────────────── 入库 ingest（离线，确定性）───────────────────────────┐
│ Markdown front-matter 打标；可选 -allow-unstructured 待审核降级导入              │
│   (id/version/title/publish/effective/scope/nature/replaces)                     │
│ → 规范文档用 SimHash 幂等；待审核文档用原始文件 SHA-256 合成身份、判定精确副本       │
│ → ## 标题解析 → 父块（节级，SectionPath 定位符）                                    │
│ → 父块内 ~300字滑窗切子块（50字重叠）→ 块级 SimHash 近重去重                        │
│ → 内存 BM25 倒排（标题+节路径参与加权）+ JSON 落盘（data/store.json）               │
└──────────────────────────────────────────────────────────────────────────────────┘
┌─────────────────────────── 检索 ask（在线，确定性）──────────────────────────────┐
│ 查询分词（unigram+bigram）→ 同义词表展开 → BM25 打分（问答使用已认证索引）            │
│ → 父块聚合（同父块留最高分）；搜索含待审核资料，问答使用已认证索引                    │
│ （as_of 时间点：inferQueryTime 从问句解析年/年月/日期/去年 → 业务时间轴过滤）        │
└──────────────────────────────────────────────────────────────────────────────────┘
┌─────────────────────────── 回答编排 engine（无模型）─────────────────────────────┐
│ 证据句抽取：句切分 → 上下文对齐分（标题+节路径+句子，单字包含度+条件词加权）           │
│   → 绝对阈值 0.34 → 相对截断（≥最强×0.6）→ 按上下文分排序                           │
│ 冲突三段式：组间最优句对 → 主题门控（标题特有字 df≤2）→ 数值互斥（同节路径+高互含>0.7）│
│   ① 时间窗不重叠 → 演变史，各答各版                                                │
│   ② 重叠+replaces 替代关系 → 规则裁决                                              │
│   ③ 重叠+无依据 → status:conflict 双方引用交人工                                    │
│ 是非问句（吗/呢/能不能）→ 须有许可/禁止性词（可以/不得/免收/退还…）才可回答            │
│ 模板组装：事实句+文档/版本/位置/摘录；指针继承显式展示新旧双来源                     │
│ 拒答：弱命中/无句子对齐/是非问无 modal 证据 → insufficient_evidence，零 citation     │
└──────────────────────────────────────────────────────────────────────────────────┘
┌─────────────────────────── 接口层 ──────────────────────────────────────────────┐
│ CLI: ingest / ask [-as-of] / search / evaluate                                    │
│ HTTP: ragbot serve → GET / (web/index.html) + POST /api/ask + GET /api/search     │
│       + GET /api/status                                                           │
│ 评测: 21 条开发查询 → Hit@5 / 来源核验 / 拒答正确率 / 耗时 → baseline JSON           │
└──────────────────────────────────────────────────────────────────────────────────┘
```

## 模块与目录

```
cmd/ragbot/        CLI 入口（组装：store → retriever → engine → server）
internal/
  types/           Document / Section / Chunk / Hit / Citation / Answer
  tokenize/        中文 unigram+bigram 分词 + 同义词表（可替换为 gse）
  simhash/         64 位 SimHash + 汉明距离（纯标准库）
  ingest/          解析/打标/分块/指纹
  store/           内存 + JSON 落盘；ingest_log 为 outbox 形态预留
  retriever/       BM25 倒排（Retriever 接口，PG/Milvus 为演化适配器位）
  engine/          证据抽取/冲突三段式/模板回答/as_of/timeparse
  evaluate/        评测链路
  server/          HTTP 模式（纯 net/http）
web/               零构建单页前端（内联 CSS/JS）
docs/              虚构语料交付物（git 追踪；README.md 为说明，ingest 跳过）
migrations/        PG schema（0001_init，含 embedding_registry 守卫表，演化位）
project-notes/     项目工作记录与设计说明（关键文件跟随 Git）
```

## 设计决策索引

| 决策 | 一句话理由 |
| --- | --- |
| 确定性优先 | 拒答/裁决在检索层与规则层，零随机、可复现、可测试 |
| 无密钥路径一等公民 | 验收首选路径；LLM/向量全是可降级增强 |
| 父子分块 | 子块命中、父块引用，excerpt 可人工定位 |
| 分层指纹 | 规范文档用 SimHash 辅助幂等；待审核文档用完整 SHA-256 验证精确副本，块级 SimHash 去重 |
| 冲突只检测不裁决 | 自动裁决错了是静默污染；标注+人审只多一次点击 |
| 时间点=业务时间轴 | effective_date/replaces 推演，问句自动解析，解析失败回退现行 |
| 标题/节路径参与打分 | 节标题承载语义；正文句可能不含查询词 |
| 是非问句 modal 门控 | "可以…吗"无许可/禁止性证据时拒答，不拼凑貌似成功的回答 |

### 非规范 Markdown 降级边界

默认导入仍要求完整 front-matter。显式使用 `-allow-unstructured` 时，缺少元数据但有正文的文件使用完整正文 SHA-256 生成 `synthetic_<hash>@unversioned`，标记 `needs_review`，保留来源文件名、别名、降级原因和正文版本提示。内容相同的文件幂等并记录别名；同名异内容独立入库并提示人工审核。未知业务日期不写入当前时间，不参与正式版本替代、时间裁决或指针跟随。资料可以出现在搜索结果，但问答使用只含已认证文档的独立检索索引；只命中待审核资料时返回 `insufficient_evidence`。损坏 front-matter、空正文和无效日期仍失败。此路径不自动生成版本或 `Replaces` 关系。

## 关键参数（dev 集调参点）

- 句子对齐阈值 0.34（ctx = 标题+路径+句子，单字包含度）
- 相对截断系数 0.6×最强证据
- 冲突主题门控：标题特有字 df≤2 + 数值互斥互含度>0.7
- 搜索中的 `needs_review` 命中分数乘 0.5；正式问答从独立已认证索引检索
- BM25 k1=1.2 b=0.75
